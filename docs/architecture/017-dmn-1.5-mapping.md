# 017 — DMN 1.5 → Nomos Mapping

Status: accepted · MVP 0.1

Nomos uses [DMN 1.5](https://www.omg.org/spec/DMN/1.5) as the native
representation of decision logic. DMN files (`decision.dmn`) are first-class
artefacts on disk; the [bpmn.io dmn-js](https://bpmn.io/toolkit/dmn-js/)
editor is embedded in the Cosmos Explorer to author them. The Go type
hierarchy in `internal/model/dmn.go` mirrors the OMG metamodel 1:1; the
parser in `internal/dmn/definitions.go` populates it from XML.

## Storage layout

```
.nomos/domains/<domain-path>/decisions/<DECISION_ID>/
  decision.yaml   # Nomos wrapper (model.Decision)
  decision.dmn    # canonical DMN 1.5 XML, source of truth for logic
```

- `decision.yaml` carries Nomos-side governance metadata (status, owner,
  number, version, summary, declared inputs/outputs, link to the DMN file).
- `decision.dmn` is the OMG DMN 1.5 XML and is round-tripped through dmn-js
  without lossy conversion.

### Boxed-expression union

The `decisionLogic` slot of a `decision` (and the encapsulated body of a
BKM, plus every nested expression position inside `contextEntry`,
`binding`, `list` items, `relation` cells, the iterator slots, etc.) can
hold any one of the twelve boxed expression types. Nomos models this as
`DMNLogic`: a tagged union with one `Kind` string and twelve pointer
fields, exactly one of which is populated. This keeps YAML/JSON
serialisation deterministic and avoids reflection-based dispatch in the
evaluator.

### TypeRef compatibility

DMN 1.0/1.1 wrote `typeRef` as a child element; DMN 1.2+ writes it as an
attribute. dmn-js (and most modern tooling) emits the attribute form. The
parser accepts both via per-struct `typeRef()` helpers so the same Nomos
model serves every DMN 1.x dialect.

## API surface

| Method | Path                                                                | Purpose                                  |
|--------|---------------------------------------------------------------------|------------------------------------------|
| GET    | `/api/v1/domains/{domain}/decisions`                                | List decisions in a domain               |
| POST   | `/api/v1/domains/{domain}/decisions`                                | Create a new decision (yaml only)        |
| GET    | `/api/v1/domains/{domain}/decisions/{id}`                           | Decision metadata (`model.Decision`)     |
| PUT    | `/api/v1/domains/{domain}/decisions/{id}`                           | Update decision metadata                 |
| DELETE | `/api/v1/domains/{domain}/decisions/{id}`                           | Remove the whole decision directory      |
| GET    | `/api/v1/domains/{domain}/decisions/{id}/dmn`                       | Raw DMN XML (loaded by dmn-js)           |
| PUT    | `/api/v1/domains/{domain}/decisions/{id}/dmn`                       | Save edited DMN XML from dmn-js          |
| GET    | `/api/v1/domains/{domain}/decisions/{id}/definitions`               | Parsed DRG as JSON (`DMNDefinitions`)    |
| POST   | `/api/v1/domains/{domain}/decisions/{id}/evaluate`                  | FEEL evaluation (decision table only)    |

## UI integration

The Cosmos Explorer renders a decision node under
`<domain>/decisions/<id>` (see `internal/server/web/templates/cosmos.html`).
Clicking the node:

1. fetches the Nomos `Decision` metadata,
2. fetches the parsed DRG (`/definitions`) for the structured side panel,
3. fetches the DMN XML (`/dmn`) — if absent, a minimal seed XML is used,
4. instantiates `DmnJS` (`/static/vendor/dmn-js/dmn-modeler.production.min.js`)
   bound to a canvas inside the detail pane, with view-switcher buttons
   for DRD / decision table / literal expression and a save button that
   PUTs the edited XML back to the API.

## Evaluation scope (MVP)

`internal/dmn/evaluator.go` evaluates the first `decisionTable` found in a
DMN file using the FEEL unary-test subset (`<`, `<=`, `>`, `>=`, `=`, `!=`,
range / interval / list expressions, dates, numbers, strings, booleans).
Other boxed expression types (`literalExpression`, `context`, etc.) are
parsed into the model but not yet runtime-evaluable. They can still be
authored, persisted, and rendered in the editor.

## Out of scope (for now)

- Programmatic mutation of `DMNDefinitions` from Go back into XML (we
  defer to dmn-js as the canonical writer). Add a writer when a non-UI
  authoring path is needed.
- Cross-file `import` resolution.
- Full FEEL expression evaluation beyond unary tests.
